# Stopscroll

Stopscroll помогает не заходить в отвлекающие сайты автоматически. На этой Linux-машине Twitch, Liquipedia, Kick и Instagram закрыты; YouTube и X открываются отдельными отрезками в пределах дневного бюджета. Начальный бюджет YouTube — 45 минут, X — 30 минут.

Ужесточения действуют сразу, ослабления ждут 45 минут в очереди. Отрезок по умолчанию длится 15 минут, предупреждение приходит за 2 минуты до конца. Новый день начинается в 04:00 местного времени. Состояние сохраняется при перезагрузке.

Служба управляет своим DNS на `127.0.0.1:5354`, настройкой systemd-resolved, таблицей `inet stopscroll` с единственным hook `output` и политиками Firefox, Chrome и Chromium. `/etc/resolv.conf`, правила ufw и Docker не изменяются. Политики Opera и Brave не устанавливаются. Другие ключи политик Firefox сохраняются.

## Установка

Нужны Linux с systemd и systemd-resolved, Python 3, dnsmasq, nftables, iproute2 (`ss`), sudo и утилиты управления пользователями. Python использует только стандартную библиотеку. Для уведомлений нужен `notify-send` и работающий графический сеанс владельца.

Из корня проекта под обычной учётной записью владельца:

```bash
sudo bash ./install.sh
stopscroll doctor
```

Установщик откажет при чужом процессе на порту 5354. Повторный запуск сохраняет состояние и принимает уже работающий DNS своей службы. Во время обновления он останавливает управляющую службу и сторож, чтобы не было двух писателей состояния. Состояние хранится в `/var/lib/stopscroll/state.json` с владельцем root и правами 0600, код — в `/usr/local/lib/stopscroll/`. Ручного файла настроек нет.

Установка успешна только при успешном `doctor`, выполненном от имени владельца; код установщика равен его коду. Ошибки синхронизации при `--init` записываются в журнал и сами по себе не гарантируют неудачный код. Если уведомитель не запустился, установка выдаст предупреждение. После входа в графический сеанс выполните:

```bash
systemctl --user daemon-reload
systemctl --user enable --now stopscroll-notify.service
```

Для диагностики служб:

```bash
stopscroll doctor
sudo journalctl -u stopscrolld.service -u stopscroll-dns.service
```

## Команды

Команды запускаются без sudo от имени владельца. Имена сайтов: `twitch`, `liquipedia`, `kick`, `instagram`, `youtube`, `x`. Минуты — положительные целые числа до 1440. Ссылки доменов нормализуются; например, `https://www.Twitch.tv/dir` становится `twitch.tv`.

```bash
stopscroll status
stopscroll open youtube 10
stopscroll open x                  # отрезок 15 минут
stopscroll close youtube
stopscroll doctor

stopscroll block youtube          # закрыть сайт, с подтверждением
stopscroll block news example.org # добавить закрытый сайт
stopscroll block news other.org   # добавить домен существующему сайту
stopscroll limit youtube 30       # уменьшить бюджет, с подтверждением
stopscroll delay 60               # увеличить задержку, с подтверждением
stopscroll block --yes news       # то же подтверждение для скрипта

stopscroll request budget youtube 60
stopscroll request bonus youtube 10
stopscroll request limit twitch 15
stopscroll request unblock news other.org
stopscroll request unblock news
stopscroll request except youtube example.org
stopscroll request delay 30
stopscroll request pause 20
stopscroll cancel 3
stopscroll request uninstall
```

`open` доступен только сайтам с лимитом и ограничен оставшимся бюджетом. Раннее `close` списывает фактически использованное время. `limit` и `delay` предназначены для ужесточения; увеличение бюджета и сокращение задержки запрашиваются через `request`.

## Задержка и восстановление

Ослабления, включая паузу и удаление, попадают в очередь с временем применения. Их видно в `status`; номер позволяет отменить изменение через `cancel`. Во время ожидания действуют прежние правила. Пауза начинает отсчитываться при применении запроса. Мгновенной штатной команды выключения нет. Изменение, ставшее неприменимым, снимается с пояснением.

Команды и изменения, создающие событие, синхронизируются сразу; изменение списка блокировки отражается в DNS не позже чем через 5 секунд. Завершение паузы и изменения без события могут ждать очередной сверки до минуты. Адреса при закрытии отрезка попадают в карантин на 120 секунд. Бюджет зависит от открытого отрезка, а не от активности вкладки.

Systemd перезапускает упавшие службы; сторож раз в минуту поднимает остановленные. Управляющая служба сверяет системные настройки раз в минуту. При падении DNS разрешение имён временно не работает; при падении управляющей службы прежние правила остаются до её восстановления. При повреждении состояния служба запускается с блокировкой.

## Известные ограничения

- Владелец с sudo может разобрать систему вручную. Это средство против автоматической привычки, а не защита от администратора.
- Перевод часов вперёд может дать свежий дневной бюджет; задержка ослабления отслеживается отдельно. Откат часов не создаёт новый бюджет.
- VPN, прокси, Tor и браузеры в контейнерах обходят блокировку. Встроенный VPN Opera и окно Tor Brave оставлены сознательно.
- Неизвестный DNS-over-HTTPS в браузере, который не читает политики, может обойти блокировку.
- После закрытия YouTube возможна заминка других сервисов Google до 2 минут из-за общих адресов; браузер может помнить DNS-ошибку до минуты после открытия.
- YouTube Music и встроенные видео входят в лимит YouTube. Вне отрезка блокируются также API и программы владельца. Docker не затрагивается.
- `accounts.youtube.com` разрешён для входа в Google; `t.co`, `twimg.com` и `ytimg.com` не блокируются.
- Клоак-браузер находится на другом устройстве; локальная приёмка его не включает. Блокировка действует только на этой машине.

## Аварийное восстановление

Если из-за сбоя пропал интернет, выполните команды root:

```bash
sudo systemctl disable --now stopscroll-watchdog.timer stopscrolld.service stopscroll-dns.service
sudo rm /etc/systemd/resolved.conf.d/stopscroll.conf && sudo systemctl restart systemd-resolved
sudo nft delete table inet stopscroll
```

Команды снимают активную блокировку; ошибки об отсутствующих файле или таблице означают, что соответствующая часть уже снята. Для полного аварийного удаления кода, состояния и политик:

```bash
sudo bash /usr/local/lib/stopscroll/uninstall.sh
```

Штатное удаление выполняется через `stopscroll request uninstall` после задержки. Сценарий удаления пробует все шаги даже при отдельных ошибках, сохраняет остальные ключи Firefox и сообщает об ошибках ненулевым кодом.
