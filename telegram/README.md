# Telegram Desktop с ограничением выбранных каналов

Здесь находятся исходный патч и инструменты сборки для Linux. Готового клиента в репозитории нет. Сначала установите [системную службу Stopscroll](../README.md), затем соберите этот клиент. Обычный Telegram не получает ограничения от установки одной службы.

Основа — [Telegram Desktop v7.4.4](https://github.com/telegramdesktop/tdesktop/tree/v7.4.4), коммит `bf4f714036f21c750d535dab199c811b3f9bfdd4`. Патч `stopscroll-tdesktop.patch` изменяет 24 файла upstream. Другие версии без адаптации не поддерживаются.

## Поведение

Клиент читает `/etc/stopscroll/telegram.json`, атомарно публикуемый root-демоном с правами 0644. Запрещённые каналы определяются по точному имени без учёта регистра и по уже распознанному числовому ID. Они недоступны через историю, профиль, ссылки, переход из пересланного поста, предпросмотр и поиск. Проверки охватывают истории, их карусель, переходы между историями, подгрузку страниц и медиагалерею канала.

Политика проверяется каждую секунду. При добавлении запрета во время просмотра текущее запрещённое содержимое закрывается после обновления политики и проверки экрана, обычно до двух секунд. При ошибке чтения сохраняется последняя корректная политика; если её ещё не было, временно закрыты все каналы. Личные переписки доступны.

После распознавания имени клиент сообщает ID через аутентифицированный Unix-сокет демона. ID добавляется к уже заблокированному имени и не заменяет ранее изученные ID. Это сохраняет запрет после переименования. До первого распознавания запрет по старому имени не найдёт уже переименованный канал.

```bash
stopscroll telegram block @example_channel --yes
stopscroll telegram block https://t.me/another_example/123 --yes
stopscroll request telegram-unblock example_channel
stopscroll status
stopscroll cancel 3
```

Добавление действует сразу; снятие — через очередь ослаблений, по умолчанию через 45 минут. Принимаются публичные `t.me`, `telegram.me` и `/s/` ссылки, приватные приглашения не подходят. Пауза сайтов не приостанавливает запреты Telegram.

[blocked-channels.example.txt](blocked-channels.example.txt) — необязательный пример с вымышленными именами, без автоматического импорта. Скопируйте его в локальный `blocked-channels.txt`, если нужен собственный список для заметок, а правила добавляйте через CLI. Реальный список исключён из git. Имена и распознанные ID в установленной политике доступны локальным пользователям на чтение.

Ограничения действуют только в этом клиенте. Telegram Web, другие клиенты и устройства остаются доступны; пересланный текст в разрешённых чатах остаётся видимым. Администратор может снять правила вручную. Нативные проверки ниже не являются проверкой GUI или входа в аккаунт.

## Подготовка исходников

Нужны Git, Python 3.11+ и Docker, доступный обычному пользователю. Helper использует закреплённый официальный образ Telegram:

```text
ghcr.io/telegramdesktop/tdesktop/centos_env@sha256:f8186fefc7d7abb23c9b7e905b7f13270f57edc7ce57bb959a2634eabe803ca3
```

Скачивание образа и рекурсивного checkout требует сети и значительного свободного места. Из корня Stopscroll:

```bash
cd telegram
git clone --depth 1 --branch v7.4.4 --recursive --shallow-submodules \
  https://github.com/telegramdesktop/tdesktop.git tdesktop
test "$(git -C tdesktop rev-parse HEAD)" = bf4f714036f21c750d535dab199c811b3f9bfdd4
git -C tdesktop apply --check ../stopscroll-tdesktop.patch
git -C tdesktop apply ../stopscroll-tdesktop.patch
```

Повторно применять патч к уже подготовленному checkout не нужно. Helper проверяет тег, происхождение HEAD от закреплённого коммита и фактический `AppVersion` (7004004). Checkout, зависимости, сборочные файлы и журналы остаются локальными и исключены из git.

## Проверки без полной сборки

Из корня Stopscroll, без Docker, checkout и учётных данных:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 telegram/tests/build_helper_test.py -q
```

Это 7 изолированных тестов helper: закрепление источника, права и редактирование журналов, классификация тестовых ключей и привязка manifest к бинарному файлу.

После подготовки checkout, из `telegram`:

```bash
python3 build.py --policy-tests
```

Команда скачивает закреплённый образ и выполняет CMake/CTest для самостоятельного модуля политики, без собственных API-ключей. Контейнер с тестами работает без сети. CMake создаёт также `stopscroll_policy_probe`. При ручной сборке без helper нужны CMake 3.25+, C++20 и Qt6 Core.

Для извлечённых регрессий поиска и историй нужны подготовленный checkout и локальный `g++` с C++20. Из корня Stopscroll:

```bash
(cd telegram/tdesktop && python3 ../channels-search-fix-test.py)
python3 telegram/stories-access-test.py
```

Первый скрипт извлекает фактические функции из изменённого `dialogs_suggestions.cpp`, проверяет фильтрацию и обновления списка и создаёт игнорируемые `telegram/channels-search-fix-test.cpp` и исполняемый файл. Второй проверяет извлечённые переходы историй и медиагалереи во временном каталоге. Это узкие регрессии со стендами зависимостей; успешный результат не подтверждает поведение всего клиента, GUI или авторизацию. В чистом исходном репозитории без checkout эти команды запускать рано.

## Полная сборка

Все дальнейшие команды сборки выполняются из `telegram`. Для тестовой сборки helper содержит **публичные тестовые** API-параметры upstream:

```bash
python3 build.py --test
```

Они предназначены только для проверки сборки. Не используйте их для повседневной работы: установщик отвергает manifest с тестовыми ключами. Даже совпадение одного API-параметра с тестовым помечает сборку как тестовую.

Для рабочего клиента получите свои `api_id` и `api_hash` через [Telegram API development tools](https://my.telegram.org). Создайте файл **вне репозитория**, по умолчанию `~/.config/stopscroll/telegram-api.json`, доступный только владельцу:

```bash
install -d -m 0700 "$HOME/.config/stopscroll"
(umask 077; touch "$HOME/.config/stopscroll/telegram-api.json")
chmod 0600 "$HOME/.config/stopscroll/telegram-api.json"
```

Заполните его локальным редактором, без публикации или вставки ключей в историю команд. Структура файла:

```json
{"api_id": 123456, "api_hash": "YOUR_32_HEXADECIMAL_CHARACTER_HASH"}
```

Значения выше — заполнители. Нужны положительный целый `api_id` и реальный `api_hash` из 32 шестнадцатеричных символов. Затем:

```bash
python3 build.py --api-file "$HOME/.config/stopscroll/telegram-api.json" \
  --full-jobs 2 --full-memory-gib 6
```

Без `--api-file` используется тот же путь по умолчанию. `--configure-only` проводит тесты и конфигурацию, но не создаёт подтверждения успешной полной сборки.

Helper собирает Debug с `-O0 -g0`, включёнными предкомпилированными заголовками и отключённым автообновлением. Внешняя сборка protobuf для bundled cld3 не нужна. Сначала собираются зависимости и генерация, затем 14 изменённых единиц трансляции, после них — оставшееся приложение. Журналы: `docker-pull.log`, `policy-tests.log`, `configure.log`, `prerequisites-build.log`, `integration-build.log`, `build.log`.

Обычные этапы ограничены двумя CPU и 4 GiB RAM, с общим лимитом RAM + swap 6 GiB. Компиляция приложения по умолчанию идёт одним процессом; `--jobs 2` меняет число процессов изменённых файлов и полной сборки. `--full-jobs 1|2|3` переопределяет только полную сборку; при 3 процессах контейнеру доступны 3 CPU. `--full-memory-gib 6` повышает RAM только полной сборки до 6 GiB, RAM + swap — до 8 GiB.

Полная сборка занимает часы. Полученный ELF может занимать около **1,4 GiB**, а checkout, зависимости и промежуточные файлы требуют существенно больше диска. Параллельная сборка при тесном лимите памяти вызывает интенсивный swap. Для полной линковки такого Debug-клиента эмпирически потребовалось временно повысить лимит контейнера с 6 до **8 GiB RAM**, с RAM + swap **10 GiB**. Helper принимает максимум 6 GiB; предусмотреть запас для линковки нужно отдельно.

При нехватке лимита во время полной сборки можно в другом терминале найти именно её активный контейнер и повысить лимиты до окончания линковки:

```bash
docker ps --no-trunc --format '{{.ID}} {{.Image}} {{.Command}}'
# Замените CONTAINER_ID идентификатором контейнера текущей полной сборки.
docker update --memory 8g --memory-swap 10g CONTAINER_ID
```

Хост должен располагать соответствующей свободной памятью и swap; эти значения не гарантируют успех на любой системе. Контейнеры helper временные (`--rm`), поэтому изменение не переносится на следующую сборку. Если сборка уже упала, повторите её и примените повышение к новому контейнеру полной сборки. Здесь нет обещания полной воспроизводимости бинарных байтов или готового релиза.

API-параметры передаются контейнеру через окружение и записываются CMake в локальные сборочные файлы. Это не секреты от администратора хоста или Docker. Helper создаёт `tdesktop/out` с правами 0700, журналы — 0600, и заменяет оба своих API-параметра на `[REDACTED]` перед записью вывода. Не публикуйте checkout, журналы или конфигурацию сборки: одних правил `.gitignore` недостаточно, если принудительно добавить файл.

Успешная полная сборка создаёт `tdesktop/out/bin/Telegram` и приватный `tdesktop/out/stopscroll-build.json`. Manifest содержит SHA256 бинарного файла, Debug-конфигурацию, отключение автообновления и признак тестовых ключей, без самих API-параметров. Перед новой конфигурацией или полной сборкой прежний manifest удаляется; неудача не подтверждает пригодность старого бинарного файла.

## Установка и запуск

Сначала успешно установите системный Stopscroll от своей обычной учётной записи. После полной сборки с собственными ключами выполните из `telegram`:

```bash
sudo bash ./install.sh
```

Установщик требует того же владельца, проверяет manifest и SHA256 до копирования и после него. Клиент устанавливается в `/usr/local/lib/stopscroll/telegram/` под управлением root, команда запуска — `stopscroll-telegram`, пункт меню — **Telegram (Stopscroll)**. Используется значок из локального upstream checkout; в этом репозитории он не поставляется.

Работающий Telegram не останавливается. Для переключения завершите его и выполните:

```bash
stopscroll-telegram
```

В GNOME установщик переключает уже закреплённый ярлык Telegram и обработчик `tg://`. Другие закреплённые приложения сохраняются. Исходные настройки сохраняются в приватном `~/.config/stopscroll/desktop.json` и восстанавливаются при удалении, с сохранением последующих изменений других приложений и обработчиков. На других рабочих столах запуск через команду остаётся основным способом.

После запуска самостоятельно проверьте разрешённые чаты, запрет выбранного канала через поиск/ссылку/профиль/истории/галерею и применение изменения во время просмотра. Вход в реальный аккаунт не входит в автоматические тесты. Сборка и установщик не копируют данные аккаунта; запуск клиента использует обычные механизмы хранения данных Telegram.

## Удаление и восстановление рабочего стола

Штатно удаляется вместе с системой Stopscroll, после задержки:

```bash
stopscroll request uninstall
```

Аварийное полное удаление описано в [корневом README](../README.md#аварийное-восстановление). Если восстановление рабочего стола завершилось ошибкой, приватная резервная копия и независимый сценарий остаются на месте. В графическом сеансе можно повторить:

```bash
python3 "$HOME/.config/stopscroll/desktop-recovery.py" restore
```

Обычный установленный Telegram и данные аккаунта не удаляются. Перед запуском обычного Telegram после удаления полностью завершите Telegram (Stopscroll).
