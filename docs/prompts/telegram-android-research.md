# Промпт для новой сессии: Telegram на Android с ограничениями Stopscroll

Мы продолжаем проект Stopscroll. Рабочий Telegram Desktop с блокировкой выбранных каналов уже создан и используется на Linux. Теперь нужно исследовать и спроектировать Android-клиент, решающий ту же задачу. Пользователь подключил **второй Android-телефон**.

**Твоя задача в этой сессии — исследование, сравнение подходов, рекомендация архитектуры и план разработки.** Не начинай полную реализацию, установку или замену Telegram до завершения этого этапа. Не считай форк официального клиента заранее выбранным решением: самостоятельно проверь варианты и предложи лучший для наших целей.

## 1. Зачем это нужно и какой результат ожидается

Пользователь тратит много времени на нежелательные Telegram-паблики. Отписка не помогает: он находит их через поиск и продолжает читать и скроллить. Нужно сохранить Telegram для обычных переписок и полезных каналов, закрыв доступ к заданному списку пабликов, включая те, на которые пользователь не подписан.

Желаемый результат дальнейшей разработки — пригодный для повседневного использования Android-клиент или другое обоснованное решение, которое:

- Использует уже существующий пользовательский список запретов и известные ID каналов.
- Не позволяет открыть запрещённый канал через альтернативный экран или переход.
- Оставляет доступными разрешённые каналы и личные переписки; обычные функции Telegram должны сохраняться в согласованном объёме.
- Работает самостоятельно на телефоне после отключения компьютера.
- Позволяет вручную читать и изменять правила с Linux-компьютера через USB, если этот способ подходит выбранной архитектуре.
- Имеет понятную сборку, установку, обновление, диагностику и восстановление.

Это средство самоконтроля на собственных устройствах. Не требуется обещать абсолютную защиту от владельца, который может установить другой клиент или снять ограничения в Android. При этом простые обходы внутри нашего клиента нужно исследовать и закрыть.

## 2. Свобода исследования

Самостоятельно изучи доступные варианты, проверь исходные предположения и сравни их. Рассмотри как минимум:

1. Изменение официального Telegram для Android, если подходящие исходники доступны и условия позволяют.
2. Использование другого поддерживаемого открытого Android-клиента или существующего форка; отдельно проверь актуальность подходящих проектов, включая Telegram X, если он применим.
3. Решение на TDLib с существующим или собственным интерфейсом.
4. Ограничения без собственного клиента: настройки Telegram, средства Android, Accessibility, управление устройством, сетевые способы и их комбинации.

Это стартовые категории, а не закрытый список. Можно предложить другой подход или отвергнуть перечисленные. Не выбирай технологию только потому, что она знакома или уже используется в другом компоненте Stopscroll.

Для каждого подхода оцени полноту блокировки, простые обходы, влияние на нормальное общение, необходимость привилегий, поддержку нескольких аккаунтов, сложность обновлений upstream, безопасность, ограничения распространения и практичность сопровождения. Главный критерий сложности — техническая реализуемость и надёжность; сроки разработки оцени отдельно и без ложной точности.

## 4. Что уже реализовано в Telegram Desktop

По сохранённым исходникам база — Telegram Desktop v7.4.4, commit `bf4f714036f21c750d535dab199c811b3f9bfdd4`. Это закреплённая база нашего патча, а не утверждение о последней версии Telegram.

- Linux-демон Stopscroll публикует `/etc/stopscroll/telegram.json` атомарно, с правами `0644`.
- Каналы сопоставляются по точному username без учёта регистра и по изученным числовым ID. Отображаемое название не является идентификатором.
- Формат опубликованной политики:

```json
{"version":1,"channels":[{"username":"example_channel","ids":["123456789"]}]}
```

- В текущем Python-контракте ID — строки с положительным каноническим числом до `2^52 - 1`. Это **не** отрицательный Bot API chat ID вида `-100…`. Для Android нужно проверить представления peer/channel ID и совместимость; не переносить преобразования наугад и не сужать типы молча.
- При распознавании заблокированного имени Desktop сообщает ID демону через аутентифицированный Unix-сокет. ID дополняют ранее известные привязки, сохраняя запрет после переименования. Пока ID ещё не изучен, неизвестное новое имя остаётся ограничением текущей модели.
- Добавление запрета применяется сразу; снятие проходит через существующую очередь ослаблений, по умолчанию 45 минут. Пауза сайтов не снимает запреты Telegram.
- Патч проверяет историю, профиль, поиск, публичные ссылки, переход из пересланного поста, предпросмотр, истории и медиагалерею. При обновлении политики уже открытое запрещённое содержимое закрывается.
- При ошибке чтения сохраняется последняя корректная политика. Без неё Desktop закрывает каналы, сохраняя доступ к личным перепискам. Для Android явно предложи и обоснуй поведение при отсутствии/повреждении политики и обновлении правил.
- Текст, уже пересланный в разрешённый чат, не удаляется. Другие клиенты и Telegram Web этим патчем не ограничиваются. Не выдавай эти ограничения за решённые.

Фактические реализации, тесты и документы важнее этого краткого пересказа. C++-код Desktop использует Qt: возможность прямого переиспользования кода и необходимость портирования нужно оценить, а не обещать. Поведенческие контракты, тестовые сценарии и нормализация могут быть полезны независимо от языка.

## 5. Что уже есть на Android и что можно переиспользовать

Это **отдельное приложение блокировки сайтов**, не Android-версия Telegram.

- Реализован локальный VpnService на закреплённой базе Rethink/Firestack. Package: `com.celzero.bravedns.stopscroll`.
- Последняя проверенная здесь сборка — `30000071`. На первом телефоне Android 13 проверены Wi-Fi IPv4, блокировка сайтов, независимые дневные бюджеты, таймеры, Doze, восстановление после обновления и перезагрузки, UI/USB-конфликты и самостоятельная работа без кабеля.
- Мобильная сеть, реальный IPv6 и физическое прохождение 04:00/DST не сертифицированы этими проверками. Даты сброса и DST покрыты host-тестами.
- Есть ручные `stopscroll android …` команды, контроль версии/подписи APK и частное хранение signing key вне Git. Фоновой синхронизации и проверок при подключении USB нет — пользователь сознательно выбрал ручное управление.
- USB-провайдер `content://com.celzero.bravedns.stopscroll.usb` проверяет Binder UID **2000** до разбора запроса. Обычные приложения, в том числе другой наш APK, не получают доступ автоматически.
- Текущий RPC имеет только пять операций: `status`, `policy.get`, `policy.replace`, `session.open`, `session.close`. Его policy описывает сайты и бюджеты, **не Telegram-каналы**. Не подменяй схемы и не добавляй к нему неподдерживаемые поля.
- Транспорт привязывается к USB-пути Linux и проверяет неизменяемую идентичность телефона и user 0 в той же shell-команде. Нет выбора TCP-устройства вместо USB или автоматического повторения мутаций. Ответы ограничены по размеру, проверяются UUID и revisions.

Android-приложение не читает Linux-файл `/etc/stopscroll/telegram.json` напрямую. Продумай перенос полной политики, её версии и изученных ID между устройствами, а не только копирование имени файла.

Оцени переиспользование инфраструктуры CLI/ADB, атомарного хранения, проверки релизов, тестовых подходов и правил публикации. Не считай, что сайтоориентированный контроллер или его журнал нужно объединить с политикой каналов. Сравни отдельный Android-клиент и варианты безопасного взаимодействия компонентов. Не ослабляй shell-only API ради удобства связи двух приложений.

Существующий VPN нужно сохранить работоспособным. Если предложенный подход использует VPN, проверь конфликт за единственный VPN-слот Android. Отдельно объясни, что сетевой фильтр может и не может сделать с выборочными каналами и контентом Telegram, вместо предположения, что нынешняя DNS-блокировка уже решает эту задачу.

На машине уже есть Android SDK и кэши инструментов в `~/.cache/stopscroll-android/`. Проверь доступные версии и свободные RAM/диск; требования Telegram могут отличаться от закреплённого VPN toolchain. Не меняй его ради нового клиента и не очищай чужие кэши или другие проекты.

Ключ VPN хранится отдельно в `~/.config/stopscroll/android-signing/`, проверенные параметры его выпуска — в `~/.config/stopscroll/android-release.json`. Не перезаписывай эти файлы метаданными Telegram. Выбор собственного package ID, отдельного или общего ключа подписи и отдельных release-метаданных входит в исследование.

Текущие списки и квоты — пользовательская конфигурация, а не константы нового проекта. Читай её штатными интерфейсами; не заменяй живые настройки примерами из документации.
